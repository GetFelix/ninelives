# Security and networking requirements

NineLives has to be very secure and fast on the network. These are the
requirements that make those two words checkable. Every decision record,
component design and kernel config change is measured against them, and
each one says how it is checked and from which milestone.

When a security requirement and a performance requirement conflict,
security wins, unless a decision record accepts a measured cost and says
why.

A requirement is changed through a pull request that says why, like a
decision record.

## Security

The [threat model](threat-model.md) says who the attacker is, what they
can reach, and which requirement stops each threat. It settled the three
questions this page left open: authenticated time (S15), encryption at rest
(S16), and CPU microcode and mitigations (S17).

| # | Requirement | Checked by | From |
|---|---|---|---|
| S1 | **Minimal surface.** A production image contains only what a listed requirement or component needs, and no interactive shell, remote login, compiler or package manager. Packages Debian requires that cannot be removed are listed in the inventory with the reason. A development image may add a serial console shell and says so in its name. | The image inventory is diffed against an allowlist in CI | M0 |
| S2 | **A hardened kernel with no loadable modules.** The built config passes [kernel-hardening-checker](https://github.com/a13xp0p0v/kernel-hardening-checker), with every option it flags either fixed or listed in `kernel/` with the reason. Unprivileged user namespaces are off, and Yama is built in with `kernel.yama.ptrace_scope` at 3. | That tool, in CI, on every kernel build; a qemu test reads `max_user_namespaces` for unprivileged use and `ptrace_scope` | M0 |
| S3 | **Read-only root.** Nothing on the root changes at run time. State lives only on the data partition, which is mounted `noexec`, `nosuid` and `nodev`, so nothing written there can run. | qemu test: writes to the root fail, and a program copied to the data partition does not run | M0 |
| S4 | **Every shipped binary is pinned and verified**: by hash and upstream signature for components ([0004](decisions/0004-components-from-pinned-releases.md)), from a pinned snapshot for packages ([0006](decisions/0006-debian-base.md)), and from a signature-checked tarball for the kernel ([0007](decisions/0007-kernel-from-upstream-source.md)). | The image build fails closed | M0 |
| S5 | **Reproducible images.** The same commit builds the same bytes, including on a clean runner with a different build path and time. No cache is used for the comparison build. Signatures are detached and the comparison is made before signing. | CI builds twice, the second time clean, and compares | M0 |
| S6 | **Each service is isolated**: its own user, its own cgroup, no capabilities except those listed for it, a seccomp filter, and Landlock limits on the files it may touch. Kernel interfaces that bypass seccomp (io_uring) are compiled out or disabled unless a decision record enables them for a named service. The list: the DHCP applier holds `CAP_NET_ADMIN`, `CAP_NET_RAW` and `CAP_NET_BIND_SERVICE`, and its seccomp filter allows netlink sockets only for `NETLINK_ROUTE`; the DHCP parser holds none and reads from a packet socket the applier hands it; the time client holds `CAP_SYS_TIME`. Each gets them as ambient capabilities from its launcher (S24). Every other service holds none, and each bounding set holds only the service's list. | The init's tests, per service: `/proc/<pid>/status` shows only the listed capabilities; the DHCP applier cannot open a `NETLINK_NETFILTER` socket | M1 |
| S7 | **Only listed ports are open**: the Felix services the role runs, the join, and the authenticated diagnostics interface (S11), each on the interfaces the role needs. The list lives in the image config. Everything else is dropped by default. | qemu test scans the machine from outside | M1 |
| S8 | **Secrets stay where they belong.** Credentials live on the data partition, readable only by the service that needs them. They are never written to the root, to console or service output, or to Felix streams. | A qemu test plants known test credentials and searches the root, captured output and the cluster's streams for them | M1 |
| S9 | **Patch deadline.** Once an upstream fix is available (Debian's security archive, a kernel.org stable release for the pinned series, or a Felix or felixd release), a fixed image is built within 72 hours for fixes Debian or the upstream rates critical or high, and within 7 days for others. Issues Debian does not fix in its security archive follow its point releases. | Advisory feeds open pull requests automatically ([#57](https://github.com/GetFelix/ninelives/issues/57)); time from fix to built image is tracked | M1 for building; M3 for running machines, when upgrades exist |
| S10 | **Mutual TLS between machines.** All traffic between machines is encrypted and authenticated with certificates from the join (S19, S20). Every Felix listener the image runs requires a client certificate where Felix can: the client port with `FELIX_TLS_CERT`, `FELIX_TLS_KEY`, `FELIX_TLS_REQUIRE_CERT=true`, `FELIX_TLS_CLIENT_CA` and `FELIX_TLS_CLIENT_CERT_BIND_SUBJECT=true`, so every client presents a certificate issued to its token's subject (the Kafka and MQTT listeners are off); the broker internal port with `FELIX_INTERNAL_TLS_CERT`, `_KEY` and `_CA`, and `FELIX_INTERNAL_ALLOW_UNAUTHENTICATED` never set; control-plane Raft with `FELIX_RAFT_TLS_CERT`, `_KEY` and `_CA` on top of `FELIX_RAFT_PEER_TOKEN`; the bootstrap listener with `FELIX_BOOTSTRAP_TLS_CERT`, `_KEY` and `_CLIENT_CA`, or off. The control-plane API takes no client CA in Felix, so it runs `FELIX_CONTROLPLANE_TLS_CERT` and `_KEY`, and its callers use an `https://` URL and `FELIX_CONTROLPLANE_CA`; the threat model lists this as a gap. felixd and every other service client present their certificate wherever the listener takes one (felixd cannot yet, [felixd#275](https://github.com/GetFelix/felixd/issues/275)). Nothing listens unauthenticated, metrics included. The one exception is the control plane's tenant JWKS, which is public keys. | A check of the image config fails on any Felix listener without a client CA, other than the control-plane API; qemu tests: on each listener, a connection without a client certificate is refused, and on the client port so is one whose certificate names a different subject than its token; a machine without credentials gets no data and cannot write | M1 ([#16](https://github.com/GetFelix/ninelives/issues/16)) |
| S11 | **A production machine can be diagnosed without a shell.** Service output and init state are kept on the data partition with a size bound, and can be read through an authenticated interface. Kernel crash dumps are kept on the data partition. A crash dump holds memory, credentials included, so reading one needs a stronger credential than reading service output. | qemu test: crash a service and the kernel, read both back; the credential that reads service output cannot read the dump | M1 |
| S12 | **Published images come with what is needed to check them**: an SBOM in SPDX built from the inventory, a build provenance attestation, and the source for every GPL component. | The release workflow fails if any is missing | First published image |
| S13 | **Verified boot and no rollback.** The firmware checks a signed kernel image, the kernel checks the root against a dm-verity hash, and a machine refuses an image older than its minimum version. The firmware's key database holds only NineLives keys, not a cloud's defaults: the Microsoft UEFI CA signs shims that boot anything their distribution signed. Signing keys are kept outside CI's reach, and how they are rotated is written down. | qemu test with secure boot on: a modified or rolled-back image does not boot, and neither does a stock signed shim | M3 ([#9](https://github.com/GetFelix/ninelives/issues/9)) |
| S14 | **A way to report vulnerabilities**, in [SECURITY.md](../SECURITY.md). | Exists | Now |
| S15 | **Authenticated time.** The clock is set only from an authenticated source: NTS (RFC 8915) servers, or the hypervisor's clock where the platform provides one. An unauthenticated source is never used. | qemu test: an unauthenticated NTP server on the test network cannot move the clock | M1 ([#59](https://github.com/GetFelix/ninelives/issues/59)) |
| S16 | **Encryption at rest.** The data partition is encrypted with authenticated encryption, so a block changed offline is refused rather than parsed, with its key sealed to the machine's measured boot, so a removed disk, a cloud snapshot or a modified image reveals nothing. Until M3 the data partition is plaintext, and the threat model says so. | qemu test with swtpm: the disk read from another machine, or booted with a modified image, yields no plaintext, and a changed ciphertext block is refused | M3, with S13 ([#60](https://github.com/GetFelix/ninelives/issues/60)) |
| S17 | **CPU microcode and mitigations.** Microcode comes from pinned Debian packages and loads before any service starts. The kernel's CPU vulnerability mitigations are never turned off by config or command line. Where they cost performance, a decision record measures the cost, and security wins (see above). | CI checks the kernel config and command line; a boot test on each cloud target fails if `/sys/devices/system/cpu/vulnerabilities` reports `Vulnerable` | M1; cloud targets M5 ([#61](https://github.com/GetFelix/ninelives/issues/61)) |
| S18 | **Each service reaches only what its role needs.** Outbound connections are limited per service user: Felix and felixd to the cluster's Felix ports, the time and DHCP clients to their servers, the join to the seeds and cloud metadata. Cloud metadata is reachable only by the join. Everything else is dropped by the kernel's packet filter. | qemu test: from each service's user, a connection to an unlisted address fails | M1 ([#62](https://github.com/GetFelix/ninelives/issues/62)) |
| S19 | **One machine, its own credentials.** Every machine has its own identity: its own Felix principal, its own certificates and tokens, none shared with another machine. Credentials expire and are renewed on the machine, so a revoked machine is cut off within one credential lifetime, and revoking it does not touch any other. Felix checks no certificate revocation, so certificate lifetime is the revocation: every certificate lives at most 24 hours and is renewed at half its life by presenting the current one to the cluster's CA. Where the CA keys live ([#16](https://github.com/GetFelix/ninelives/issues/16)) gates all of this. A secret that an upstream requires machines to share is listed in the threat model with how it is rotated. | qemu test: revoke one machine of three; within one certificate lifetime it can no longer read or write, and the other two keep working; a certificate is renewed before half its life passes | M1; the revocation test M2 ([#63](https://github.com/GetFelix/ninelives/issues/63)) |
| S20 | **An authenticated join.** A join token is single use, expires, names one role, and is refused once used; join attempts are rate limited. The joining machine checks the core machines against a CA fingerprint in its join config before it sends the token. The join issues the machine's first certificates. Felix's bootstrap listener runs only on loopback and only while the cluster forms, and dev tokens are never on in a production image. | qemu tests: a used, expired or wrong-role token is refused; a machine shown a core machine with another CA does not send its token; bootstrap is closed once the cluster has formed | M1 ([#64](https://github.com/GetFelix/ninelives/issues/64)) |
| S21 | **The pipeline's own inputs are pinned.** Every tool, Action and script CI runs is pinned by commit or SHA-256, and the runner image by version. Pull request workflows get a read-only token and no secrets; only the release workflow, on a protected tag, reaches publishing credentials. | A CI check fails on an unpinned download or Action | Now ([#65](https://github.com/GetFelix/ninelives/issues/65)) |
| S22 | **Authenticated, fresh, safe updates.** A machine accepts an update only if it is signed by the image key, newer than its minimum version (S13), and described by update metadata that has not expired. Each machine reports its image version to the log, and one past the S9 deadline is reported. A production machine refuses a development image. Rollback never goes to an image whose Felix cannot read the data partition, and a cluster never updates more machines at once than it can lose. | qemu tests for each refusal; the M3 upgrade test checks staging | M3 ([#8](https://github.com/GetFelix/ninelives/issues/8), [#66](https://github.com/GetFelix/ninelives/issues/66)) |
| S23 | **Reproducible components are rebuilt before they are pinned.** For a component whose upstream publishes reproducible builds, the job that opens a bump pull request ([#52](https://github.com/GetFelix/ninelives/issues/52)) rebuilds it from the tagged source and fails if the bytes differ from the release, so a signed release built from other source does not ship. | The bump job | M1 ([#67](https://github.com/GetFelix/ninelives/issues/67)) |
| S24 | **No root after early boot.** No process runs as uid 0 once early boot ends, PID 1 included. PID 1 keeps only `CAP_KILL` and `CAP_SYS_BOOT`; before it drops, it forks one launcher per service at that service's uid, non-dumpable. Securebits `NOROOT` and `NO_SETUID_FIXUP` are set and locked, and every service runs with `no_new_privs`. `/proc/sys` is read-only after boot, `kernel.core_pattern` is fixed on the kernel command line to a path, never a pipe, and `kernel.yama.ptrace_scope` is 3. No root-owned file is writable after the drop. The packet filter is loaded before the drop, and no service may use `NETLINK_NETFILTER`. No root login or shell, and no binary in the image has a setuid bit or file capabilities. | The image build fails on a setuid bit or a `security.capability` attribute; qemu test: after boot no process but kernel threads has uid 0; `/proc/1/status` shows `CapEff` and `CapPrm` of `CAP_KILL` and `CAP_SYS_BOOT` only and locked securebits; every service shows `NoNewPrivs: 1`; `setuid(0)` from PID 1 fails; `core_pattern` does not start with `\|`; `ptrace_scope` reads 3; as each service uid, a scan finds no root-owned file it can write | M1 ([#68](https://github.com/GetFelix/ninelives/issues/68)) |
| S25 | **A compromised machine is replaced, not cleaned.** An operator who judges a machine compromised runs the replacement; nothing triggers it automatically, because a compromised machine's own reports cannot be trusted. It runs from outside the machine, through the hypervisor or a reimage, never on the machine itself, which a root attacker would ignore: the disk is destroyed (with S16, its key discarded), its principal is revoked, and its certificates are not renewed. For a core machine, the Raft peer token is rotated on every remaining member, every tenant signing key is staged, activated and the old one retired, and the Raft certificates are reissued, since any of them can speak for any member. The machine rejoins under a new identity with new credentials, and nothing from its old disk is kept. | qemu test, run after one certificate lifetime has passed: replace one of three machines from the host; its old tokens and certificates are refused everywhere; for a core machine, so are the old Raft peer token and tokens signed by the old keys; it rejoins under a new identity | M2 ([#75](https://github.com/GetFelix/ninelives/issues/75)) |

## Networking

Felix's traffic is QUIC over UDP between brokers, control planes and
agents: many connections, small and large messages, and writes that wait
for replicas. QUIC's congestion control runs in Felix's process, not the
kernel, so the kernel's job is to move UDP datagrams in batches and stay
out of the way.

| # | Requirement | Checked by | From |
|---|---|---|---|
| N1 | **No slower than a general-purpose system.** Felix's benchmark matrix run on NineLives matches the same cloud machines running Debian 13 with its stock kernel and Felix's documented tuning, on throughput and latency, for every cell, within the run-to-run noise band the matrix measures. Both runs use the same Felix settings; if the baseline gains from a kernel feature NineLives compiles out (io_uring, for Felix's optional flusher), that is reported as its own cell and decided by a decision record, not hidden. A cell outside the band blocks the change that caused it. | The matrix on identical cloud machines ([#58](https://github.com/GetFelix/ninelives/issues/58)) | M2 |
| N2 | **The kernel gives Felix's QUIC stack what it uses**: UDP segmentation and receive offload (GSO and GRO) and batched send and receive. | qemu test: GSO and GRO are available on the image's UDP sockets (probed with `UDP_SEGMENT` and `UDP_GRO`); a Felix-level check once Felix reports them | M1 |
| N3 | **Every tuning is measured.** A sysctl, qdisc, socket buffer, IRQ or CPU setting goes in with the benchmark result that justifies it, and comes out if a later measurement says it no longer helps. Nothing goes in because it is commonly recommended. | Review | M1 |
| N4 | **Workloads cannot starve the log.** On a shared machine, Felix's p99 publish latency under a workload saturating CPU and memory stays within the noise band of the same run without that workload. | A cloud test with a saturating workload | M2 |
| N5 | **Failover is measured.** The three-VM demo reports how long a workload took to resume, every run, kept as a CI artifact and appended to a history file in the repo's perf data. Once ten runs exist, a run more than twice the median of the last ten fails; before that, results are reported only. | The M2 demo ([#7](https://github.com/GetFelix/ninelives/issues/7)) | M2 |
